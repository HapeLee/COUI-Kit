# Agent Note: 普通文档按使用者与贡献者分层

Status: implemented

## Problem

根 README、库 README、接入、兼容、Developer 与复刻指南混合了接入、架构、维护细节和检查记录。使用者需要跨文件甚至进入研究笔记才能确认装配；贡献者也缺少组件及效果文档的更新规则。AI 开发需要明确的阅读入口和完整流程。

## Decision

根 README 提供项目介绍与使用导航，AGENTS 提供开发任务阅读入口，CONTRIBUTING 说明贡献流程，不另设 docs 首页。guide 持有源码接入、兼容、外观及 Demo；components 按控件提供用法；effects 按独立绘制能力提供单位、坐标、采样、合成和资源要求。公共使用要求在所属页完整维护，研究笔记用于追溯理由。

development 分别维护开发流程、架构、API、代码规范、复刻方法、文档维护及验证。原厂目标、实际消费者、状态路径、双向核查与 1:1 要求继续生效，复刻指南的原厂链路和排错案例保留。CONTRIBUTING 是协作入口，AGENTS 按任务要求先阅读流程与代码规范，并对行为改动指向复刻方法和当前代码。

新增或改变 component / effect 的使用契约时，同一个 PR 更新对应普通文档、目录、示例与受影响页面。文档维护页提供两类页面的写法、改动矩阵和参数单一来源要求；PR 模板收集文档路径、用法影响或无需修改的原因。旧入口移除，入站链接改到新位置。

保留 coui 与 demo 两模块，只使用 Markdown；VitePress、站点导航搜索、Maven 与发行配置暂缓。本次不调整组件 API、运行行为、构建或依赖。

## Alternatives considered

- **保留原文件，只增加一个导航索引。** 迁移少，但混合职责与装配规则重复仍在，无法让组件页独立回答接入问题。
- **先建设 VitePress 网站，再整理内容。** 可以直接提供导航和搜索，但用户暂缓站点工作，工具链也不能修正文档内容的归属；先交付可在仓库中阅读的结构。
- **使用文档只列 API 和 Demo 链接。** 维护量小，却要求使用者阅读完整 App 才能分辨状态、平台与坐标契约；每页保留真实用法与必要限制。

## Consequences

使用与贡献各有明确入口，组件与效果可单独查阅。代价是公开契约变更时必须同步对应页面及其示例；通过文档维护规则和 PR 模板明确责任。文档不手工复制整套默认参数，也不因尚未配置站点而保留空页。

旧普通页面路径改变，仓库内的链接与活跃 Note 同步更新。Markdown 路径、锚点、目录可达、旧路径残留、Note 结构与差异检查通过；19 段 Kotlin 示例通过 PSI，58 个 COUI 导入与 41 处公开调用对照当前声明检查了可见性及参数。检查器不做 Android 类型编译，也不验证设备运行；临时检查器不加入仓库。
