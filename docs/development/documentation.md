# 文档维护规范

本规范面向库维护者，规定各层文档的唯一归属、变更同步触发条件，以及对外使用文档的编写模板与禁用写法。

## 受众分层与文件归属

仓库文档分为**外部调用者文档**与**内部维护者文档**。同一规则只在唯一位置完整维护，其余位置引用链接。

| 位置 | 受众 | 唯一维护内容 |
| --- | --- | --- |
| 根 `README.md` | 外部 | 项目定位、快速接入、文档总导航与外部 Skill 入口 |
| `docs/guide/` | 外部 | 依赖与工具链基线、兼容门槛、主题适配、宿主接入、Demo 说明 |
| `docs/components/` | 外部 | 控件定位、推荐默认用法、高频业务场景、约束与避坑 |
| `docs/effects/` | 外部 | 独立绘制效果的用法、坐标系、采样合成、生命周期与失败行为 |
| `skills/coui-kit/` | 外部 AI | 面向外部接入者的极简红线、默认调用模板与高频避坑速查 |
| `AGENTS.md` | 维护 AI | 任务阅读入口、执行权限与跨仓库硬性边界 |
| `docs/development/` | 维护者 | 开发与复刻流程、架构职责、代码/API 规范、文档规范、验证与发布 |
| `.agents/notes/` | 维护者 | 非平凡设计决定的理由、备选方案、取舍与历史证据 |
| 源码 KDoc 与构建配置 | 全员 | 完整参数声明、默认值、精确常量与构建基线 |

## 变更同步触发矩阵

代码或规则改动时，按受影响范围在同一个 PR 内同步对应文档：

| 改动类型 | 须同步的文档 | 说明 |
| --- | --- | --- |
| 新增 component / effect | `docs/components/` 或 `docs/effects/`、对应目录 README、`skills/coui-kit/` | 补公开示例、源码入口与必要避坑；按范围补 Demo |
| 重命名或移除公开入口 | 受影响页面、目录、入站链接、`skills/coui-kit/` | 迁移方式写入 PR，发行时记入 `CHANGELOG.md` |
| 参数、回调、状态或生命周期语义变化 | 对应使用页、`skills/coui-kit/` | 更新推荐调用方式与状态归属 |
| API 门槛、依赖、采样或失败行为变化 | `docs/guide/compatibility.md`、受影响使用页、`skills/coui-kit/` | 保留明确版本与降级边界 |
| 新增或暴露出高频接入踩坑 | 对应使用页、`skills/coui-kit/` | 用极简反例或警示列出根因与修正 |
| 纯内部重构或仅调整实现参数（契约不变） | 按需更新 `docs/development/`、KDoc 或 Note | **不修改**使用页与 `skills/coui-kit/`；PR 说明契约未变原因 |

> [!IMPORTANT]
> `skills/coui-kit/` 只保留外部接入必需的高密度要点、最小调用片段与避坑红线；不要把整篇组件文档或大量样板代码搬入 Skill。

## Component 页面模板

文件名使用英文小写和连字符，与 [组件目录](../components/README.md) 一致。单页推荐控制在 **80–160 行**，固定按以下 4 段组织（不建空章节）：

1. **定位与门槛**（2–4 行）：一句话说明用途、所在包名、最低 Android 版本、所需采样源或可选模块（如 `coui-material3` / `coui-icons`）。
2. **最小可用用法**（5–12 行核心代码）：直接展示省略 `dark` / `colors` / `style` 的默认推荐接法，配合 1–2 句说明状态归属。
3. **高频场景**：挑选 2–4 个真实装配场景（如整行开关、异步 `loading`、材质弹窗、第三方容器接线）。仅在确实需要覆盖配色或形状时单列“自定义外观”短节。
4. **约束与避坑 + 源码与 Demo 入口**：集中列出 `require`/`check` 抛错条件、Modifier / Insets / 采样顺序、易错对比（如 `Dialog` 显式传 `material`、`Item.enabled` 不变灰），文末给出公开源码与 Demo 文件链接。

可参考 [滑条](../components/slider.md) 和 [菜单](../components/menu.md) 的契约表达，编写时同时遵守下文反模式清单。

## Effect 页面模板

像素效果与算法页按以下 5 段组织，不强加组件式点击或业务状态章节：

1. **可见结果与入口分层**：说明视觉效果，区分便捷入口与底层自定义。
2. **输入、单位与坐标系**：明确本地、窗口、屏幕坐标与 px/dp 责任边界。
3. **采样与合成层序**：说明是否需要背景源、源与消费者分层，以及遮罩/`alpha` 含义。
4. **资源与生命周期**：明确谁持有可变 `renderer`、图层何时创建与释放。
5. **平台门槛、失败行为与源码链接**：列出 API 门槛、异常抛出与替代路径，禁止把不同算法写成等价。

可参考 [阴影](../effects/shadow.md) 与 [融合](../effects/metaball.md)。

## 示例与措辞反模式

编写或审查对外文档时，以下写法**必须删除或改写**：

- **禁止假想多参包装壳**：不要把 5–10 行调用包成带 8–12 个参数的 `fun XxxExample(modifier, checked, dark, accent, title, ...)`。直接写最小 `@Composable` 调用片段并标注所需作用域（如“在 `ColumnScope` 或 `Scaffold` 槽位内调用”）。
- **禁止基础示例绕开主题默认**：基础示例不要显式传入 `dark`、`accent`、`colors` 或 `CouiXxxDefaults.colors(...)`，应直接展示零配置走主题的默认写法。
- **禁止复制全量默认值表**：不在使用页维护“参数名 | 默认值 | 说明”全量表；完整参数列表与默认值以源码 KDoc 为唯一真相源，文档只解释关键参数与易错组合。
- **禁止历史叙事与冗余保证**：删除“已改为”“现已支持”“仍保留旧调用”等过渡性描述（版本差异归 `CHANGELOG.md`，决策原因归 Note，单轮验证归 PR）。
- **禁止暴露内部实现或研究过程**：不把 `internal` 辅助类写成接入入口；原厂反编译链路放在 [复刻指南](replication-guide.md) 或 Note，不写入使用页；不用占位图冒充真实渲染效果。

## 提交前检查

1. 基础示例是否已省略外观可选参数，直接走默认主题？
2. 是否已核对源码中的 `require` / `check` 条件，并把易触发崩溃的约束写入「约束与避坑」？
3. 是否已清理重复的默认值表、假想包装函数与变更历史叙述？
4. 公开契约变动是否已同步目录索引、入站链接及 `skills/coui-kit/`？
5. 是否已运行 `git diff --check`，并在 PR 中列出修改的文档路径（或说明契约未变的原因）？
